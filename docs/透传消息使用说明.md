# 项目中透传消息使用说明

本项目基于野火 IM（WildFireChat），透传消息对应 **`PersistFlag.Transparent`** 类型的消息。

---

## 一、发送透传消息

透传消息的**内容类型**必须带 `@ContentTag(..., flag = PersistFlag.Transparent)`（如 `NoticeInformMessageContent` 或自定义类型）。发送方式与普通消息相同，由 **`ChatManager.sendMessage`** 完成。

### 1. 构造会话与内容

```kotlin
import cn.wildfirechat.model.Conversation
import cn.wildfirechat.remote.ChatManager

// 单聊：发给指定用户
val conversation = Conversation(Conversation.ConversationType.Single, "目标用户 userId", 0)

// 群聊：发给指定群（透传支持单聊、群聊；不支持 ChatRoom）
// val conversation = Conversation(Conversation.ConversationType.Group, "群组 groupId", 0)

// 透传内容：使用已注册的透传类型，例如自定义的 MyPassthroughMessageContent
val content = MyPassthroughMessageContent().apply {
    cmd = "refresh"
    data = "{\"id\":\"123\"}"
}
```

### 2. 调用发送 API

```kotlin
ChatManager.Instance().sendMessage(
    conversation,
    content,
    null,           // toUsers：定向用户，null 表示发给会话所有人
    0,              // expireDuration：0 永不过期，单位毫秒
    object : SendMessageCallback {
        override fun onSuccess(messageUid: Long, timestamp: Long) {
            // 发送成功（对方在线才会收到，透传不存离线）
        }
        override fun onFail(errorCode: Int) { }
        override fun onProgress(progress: Long, total: Long) { }
        override fun onPrepare(message: Message?, savedTime: Long) { }
        override fun onMediaUpload(message: Message?, remoteUrl: String?) { }
    }
)
```

**说明**：透传可由**客户端**发，也可由**服务端**通过野火 API 推送；对方不在线会丢弃，且不支持聊天室。

---

## 二、接收透传消息

透传消息与普通消息走同一条通道，在 **`OnReceiveMessageListener.onReceiveMessage`** 里统一收到，根据 `message.content` 的类型区分处理。

### 1. 注册监听（通常已在 MainBroadActivity 等处注册）

```kotlin
import cn.wildfirechat.remote.ChatManager
import cn.wildfirechat.remote.OnReceiveMessageListener
import cn.wildfirechat.model.Message

ChatManager.Instance().addOnReceiveMessageListener(object : OnReceiveMessageListener {
    override fun onReceiveMessage(messages: MutableList<Message>?, hasMore: Boolean) {
        messages?.forEach { message ->
            when (message.content) {
                is NoticeInformMessageContent -> {
                    // 项目已有的透传：系统公告
                    val bean = message.content as NoticeInformMessageContent
                    // 使用 bean.id、bean.noticeTitle、bean.pushData 等
                    EventBus.getDefault().post(NoticeInfoBroadBean(...))
                }
                is MyPassthroughMessageContent -> {
                    // 自定义透传
                    val content = message.content as MyPassthroughMessageContent
                    // 根据 content.cmd、content.data 做业务逻辑
                }
                else -> { /* 其他消息类型 */ }
            }
        }
    }
})
```

### 2. 项目中的实际接收位置

- **文件**：`app/src/main/java/com/cboda/intelligent/MainBroadActivity.kt`
- **逻辑**：在 `addOnReceiveMessageListener` 回调里判断 `message.content is NoticeInformMessageContent`，然后发 EventBus `NoticeInfoBroadBean`；自定义透传可在此处增加 `is MyPassthroughMessageContent` 等分支。

**要点**：只要该消息类型的 `getPersistFlag()` 为 `Transparent`，就会只在线推送、不存库，并在上述 `onReceiveMessage` 中收到。

---

## 三、透传消息特点

（见 `chat-client/.../message/core/PersistFlag.java`）

- **服务器透传**：只做转发，不落库
- **对方不在线会丢弃**：不会存离线、不会补发
- **不同步到发送方多端**：发送方其他设备收不到
- **不支持聊天室**

适合：实时指令、状态同步、在线通知等「仅在线生效」的场景。

---

## 四、项目中已有示例：NoticeInformMessageContent

- **定义**：`chat-client/.../message/NoticeInformMessageContent.java`
- **类型**：`@ContentTag(type = MESSAGE_CONTENT_TYPE_SYS_NOTICE_INFORM, flag = PersistFlag.Transparent)`
- **用途**：后端在线推送的系统公告，数据放在 `payload.pushData` 的 JSON 里
- **注册**：在 `ChatManager` 初始化时已 `registerMessageContent(NoticeInformMessageContent.class)`（见 ChatManager 初始化代码）
- **接收处理**：在 `MainBroadActivity` 的 `OnReceiveMessageListener.onReceiveMessage` 中，根据 `message.content is NoticeInformMessageContent` 处理，并通过 EventBus 发 `NoticeInfoBroadBean`

## 五、如何新增一种透传消息

### 1. 定义消息内容类

在 `chat-client` 或业务模块中新建类，继承 `MessageContent`，并加上 **`PersistFlag.Transparent`**：

```java
// 1. 在 MessageContentBroadType 中增加 type 常量（自定义消息需 ≥ 1000）
// 例如：int MESSAGE_CONTENT_TYPE_MY_PASSTHROUGH = 6002;

// 2. 定义消息类
@ContentTag(type = MESSAGE_CONTENT_TYPE_MY_PASSTHROUGH, flag = PersistFlag.Transparent)
public class MyPassthroughMessageContent extends MessageContent {
    public String cmd;
    public String data;

    @Override
    public void decode(MessagePayload payload) {
        // 从 payload.content 或 payload.pushData(JSON) 解析
    }

    @Override
    public String digest(Message message) {
        return "[透传]";
    }

    @Override
    public MessagePayload encode() {
        MessagePayload payload = super.encode();
        payload.content = ...;  // 或用 payload.pushData 存 JSON
        return payload;
    }
    // Parcelable 相关：writeToParcel、CREATOR 等
}
```

- 服务端下发的数据可放在 `MessagePayload.content` 或 `MessagePayload.pushData`（JSON），客户端在 `decode` 里解析。

### 2. 注册消息类型

在应用初始化时（如 `MyBroadApp` 或 ChatManager 初始化处）注册：

```kotlin
// Kotlin
ChatManager.Instance().registerMessageContent(MyPassthroughMessageContent::class.java)
```

与 `NoticeInformMessageContent` 的注册方式一致。

### 3. 接收并处理透传消息

在已注册的 **`OnReceiveMessageListener`** 里（例如 `MainBroadActivity` 中）根据 `content` 类型分支：

```kotlin
ChatManager.Instance().addOnReceiveMessageListener(object : OnReceiveMessageListener {
    override fun onReceiveMessage(messages: MutableList<Message>?, hasMore: Boolean) {
        messages?.forEach { message ->
            when (message.content) {
                is MyPassthroughMessageContent -> {
                    val content = message.content as MyPassthroughMessageContent
                    // 根据 content.cmd、content.data 做业务处理（如弹窗、刷新、发 EventBus 等）
                }
                // 其他类型...
            }
        }
    }
})
```

透传消息也会走同一条 `onReceiveMessage`，只是 `content` 的 `getPersistFlag()` 为 `Transparent`。

### 4. 发送透传消息（通常由服务端发起）

- **透传**一般由**服务端**通过野火服务端 API 向指定用户/会话推送，客户端只负责「接收 + 处理」。
- 若确需客户端发：使用 `ChatManager.Instance().sendMessage(conversation, content, ...)`，只要 `content` 对应的类型注册为 `PersistFlag.Transparent` 即可；注意限制（不存离线、不支持聊天室等）。

## 七、小结

- **用透传**：定义 `MessageContent` 并设 `@ContentTag(..., flag = PersistFlag.Transparent)`，注册后在 `onReceiveMessage` 里按类型处理。
- **数据来源**：通常由服务端推送，客户端在 `decode` 中解析 `payload.content` / `payload.pushData`。
- 参考实现可直接看 **NoticeInformMessageContent** 和 **MainBroadActivity** 中的处理逻辑。
